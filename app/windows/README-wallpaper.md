# Wallpaper layer (Windows runner)

- Build and run: `flutter run -d windows` from `app/`. No flags = wallpaper mode: a borderless, colour-keyed, full-screen window parked behind the desktop icons. `--window` shows the same stage in a plain dark window (no WorkerW trick, for testing); `--room` opens the old pixel room, `--fake` still applies there.
- WorkerW trick (`runner/desktop_layer.cpp`): `FindWindow("Progman")` gets `0x052C`, which makes the shell spawn a WorkerW behind `SHELLDLL_DefView` (on 24H2 as a child of Progman, earlier as the sibling right after it); the window is `SetParent`ed under it, so the icons draw over it and the user's wallpaper shows wherever Flutter paints `DesktopStage.keyColor` (RGB 1,2,3, `LWA_COLORKEY`; DWM alpha does not reach a child of WorkerW).
- A window down there gets no mouse input (the icon list view covers the screen), so a 40 ms timer polls the cursor: inside a hit rect Dart reported (character, open bubble) and with only the desktop under the cursor, the window is raised to a topmost top-level window; it goes back when the cursor leaves unless Dart pinned it (`bringToFront`, bubble open). While raised it is `WS_EX_TRANSPARENT` outside the rects, and `WM_NCHITTEST` answers `HTTRANSPARENT` there.
- Dart side: `lib/desktop/desktop_layer.dart` (channel `agent_office/desktop`: `enterWallpaperMode`, `bringToFront`, `sendToBack`, `setHitRects`, `screenSize`, `quit`; the runner calls back `focusLost` when another process took the foreground while a bubble was open).
- Exit: the layer has no chrome. Esc while the layer has keyboard focus and no bubble is open quits (so Esc twice: close the bubble, then quit); otherwise close `agent_office_app.exe` from Task Manager (`taskkill /im agent_office_app.exe`). A tray icon comes in step 3.
- Not compiled here (Linux box, no MSVC): if the build complains, the likely spots are `desktop_layer.cpp` (Win32 calls, /W4 /WX) and the `MethodChannel` lambda in `flutter_window.cpp`.
- If the character stays invisible, check (a) `FindWorkerW` found a window (the debug console prints "behind the desktop icons" or "no WorkerW"); (b) on 24H2 the Progman child WorkerW may need `SetWindowPos(workerw, HWND_BOTTOM, ...)` under `SHELLDLL_DefView`; (c) with per-monitor DPI the window covers the primary monitor only (`SM_CXSCREEN`/`SM_CYSCREEN`).
- The folder picker (`file_selector_windows`) owns its dialog by the raised layer, so it only opens while a bubble is open and the layer is in front.
